# 요구사항과 설계 결정 기록

기준일: 2026-10-29 KST. 대화에서 확인한 요구사항과 설계 판단의 요약이다. 구현 상태는 [ARCHITECTURE.md](ARCHITECTURE.md)를 따른다. 변경 시 날짜·변경 이유·이전 결정을 대체하는지 남긴다.

표기: **사용자 확정** = 대화에서 직접 정한 방향, **설계 제안** = 구현자의 선택으로 재검토 가능, **실험 가정** = 실행 예시일 뿐 전략 채택이 아님, **미결정/미검증** = 확인 전 적용하거나 성과를 주장하지 않음.

## 1. 사용자 확정 사항

| ID | 내용 | 해석과 경계 |

사용자의 “상시 -2% 안에서 손절”은 **목표**다. 실제 손실 보장은 확정하지 않았다. 현재 `maxInitialRiskPct=0.02`는 진입 시 계획 위험 검사다. 본절 스탑 역시 갭·슬리피지·비용·거래 불가 구간을 제거하지 않는다.

이전 `강의 노트.md`의 25%/25% 익절 및 일봉 중심 구현 범위와 충돌하는 경우, 위 최신 요구와 해당 노트의 2026-10-29 추가 기록을 따른다. 강의 원칙·사용자 추가 규칙·코드상의 가설은 같은 것으로 취급하지 않는다.

D07은 현재 구현 범위이지 “종가 보유 물량에 장중 물량을 더하지 말라”는 사용자 확정 규칙이 아니다. 이미 보유한 종목에 추가 진입하는 전략을 지원하려면 물량별 원가·익절·보호와 합산 위험을 먼저 정의해야 한다.

## 3. AWS 및 학습 설계 제안

- **D09 — 활성/대기 실행기와 단일 주문 주체:** ECS on EC2, DynamoDB 상태/실행권, 증권사 대조를 조합한다. 포지션 보호의 연속성을 위해 검토하는 목표 구조이며 미구현이다.
- **D10 — CPU 추론 우선, 학습은 별도:** 미래 학습 코드는 Python 생태계를 우선 검토한다. 지도학습과 강화학습을 오프라인에서 수행하고 검증한 모델만 실행기에 배포한다. 모델 크기·GPU 필요성·추론 형식은 아직 미정이다.
- **D11 — 연구와 기록은 비동기 작업으로 분리:** Bedrock/AgentCore, Fargate, S3를 검토한다. 실시간 손절 루프는 리서치·학습 완료를 기다리지 않는다.
- **D12 — 강화학습은 기준 모델 이후:** 라벨/시점/비용/검증이 먼저다. 강화학습 사용 자체가 승률이나 순수익 향상을 보장하지 않는다. 보호 규칙 변경 권한을 모델에 주지 않는다.
- **D14 — 반도체 분봉 모델 연구 순서:** 2026-10-29 제안. 데이터 계약과 시점별 종목 목록 → 인과적인 후보·라벨 → 단순 모델과 LightGBM → 시간 순서 검증 → 잠근 기간 평가 → 실시간 모의 순서로 진행한다. 상세는 [MODEL_RESEARCH.md](MODEL_RESEARCH.md)를 따른다. 장중 후보 평가부터 검증하는 개발 순서이며 종가베팅 병행 요구를 대체하지 않는다.

### 비용 검토의 보존용 메모

이전 대화의 **계획용 추정치**는 상시 이중 실행·네트워크·기본 저장/감시·리서치 월 약 **$320–470**, GPU 학습 100시간을 더해 약 **$400–650**였다. 원화 약 **60–98만 원**은 환율 1,500원/$를 가정한 환산이며 현재 환율이 아니다.

이 수치는 배포 견적이나 검증된 사용료가 아니다. 전제는 서울 리전, 실행기 2대, NAT 2개, 소규모 데이터·리서치 사용량과 학습 100시간이었다. 학습 반복 횟수, GPU 종류, 원본 시세 보관량, LLM 토큰, 데이터 제공료·세금·운영 인건비에 따라 크게 달라진다. 단일 호스트 모의 단계와 목표 이중화 구성을 같은 비용으로 보지 않는다. 배포 전에 [EC2](https://aws.amazon.com/ec2/pricing/on-demand/), [VPC](https://aws.amazon.com/vpc/pricing/), [SageMaker](https://aws.amazon.com/sagemaker/ai/pricing/) 공식 요금과 실제 구성으로 다시 산정한다.

## 4. Rust 전환 평가 — D13

**현재 권고: 전면 재작성은 보류하고, 실거래 실행 엔진의 Rust 분리 가능성을 열어 둔다.** 이는 아직 사용자 확정이나 구현 지시가 아닌 기술 판단이다.

### 의미가 있는 부분

Rust의 소유권 검사는 가비지 컬렉터 없이 메모리 안전성을 제공한다. 오래 실행되는 시세 처리·포지션 상태 전이·위험 검사·주문/보호 루프에서 메모리 사용과 지연 변동을 관리하는 데 유리할 수 있다. 타입으로 잘못된 상태 전이를 줄이는 설계도 가능하다. AWS SDK for Rust가 있어 S3·DynamoDB 등의 연동 경로도 있다. 다만 실제 실행 지연과 안정성은 구현·저장소·네트워크·브로커까지 측정해야 한다. 근거: [Rust 공식 소유권 설명](https://doc.rust-lang.org/book/ch04-01-what-is-ownership.html), [AWS SDK for Rust](https://docs.aws.amazon.com/sdk-for-rust/latest/dg/welcome.html).

### 지금 전면 전환하지 않는 이유

- 실제 시세의 입력량·CPU·메모리·이벤트 루프 지연·p95/p99 처리 지연을 아직 측정하지 않았다. Rust 전환으로 개선될 병목이 확인되지 않았다.
- 동시 보유 3종목은 시세 구독량과 다르다. 후보 감시 규모와 이벤트 속도가 정해져야 처리 용량을 판단할 수 있다.
- 현재 엔진은 이벤트마다 JSON 상태 복제·설정 해시 검사와 동기 SQLite 트랜잭션을 수행한다. 동일 프로세스의 영속화 지연이 후보 병목이다. 언어보다 저장 경로를 먼저 바꿔야 할 수도 있다.
- 학습 데이터·패턴 정의·실거래 주문 대조·장애 복구가 아직 남아 있다. 언어를 바꿔도 이 기능은 새로 설계·검증해야 한다.
- Rust도 주문 결과 미상, 브로커 제한, 시세 유실, 체결 갭, 본절 청산 실패를 해결해 주지 않는다. 승률 개선은 별도의 학습·검증 문제다.

### 권장하는 경계

| 영역 | 초기 선택 | 이후 검토 |
|---|---|---|
| 일봉 스캐너·리서치 연결·실험 CLI | 기존 Node.js 유지 | 필요한 기능 중심으로 유지 |
| 라벨링·지도학습·강화학습 | 미구현; Python 우선 검토 | 모델·데이터 규모로 학습 환경 결정 |
| 시세·포지션·위험·주문·보호 | 현재 Node.js 모의 엔진 | 요구 확정 후 Rust 실행 엔진 후보 |
| 실시간 모델 추론 | 현재 규칙만 존재 | 모델 형식과 지연 측정 후 로컬 추론/별도 서비스 선택 |

실행 엔진 분리 여부를 판단할 때는 실제 수신량과 순간 폭주를 재생해 수신→판단→영속화 지연, 이벤트 루프 정체, 메모리, 재시작·잔고 대조 시간을 측정한다. 지연 허용치와 복구 목표는 먼저 정하고, 측정 결과가 넘거나 안전한 상태 관리·장기 유지보수 요구가 충분하면 Rust를 채택한다. 임의의 “몇 배 빠르다”는 성능 수치는 제시하지 않는다.

전환한다면 이벤트 스키마·규칙 버전·금액 단위를 먼저 고정하고, 같은 입력에 대한 주문 의도·손절 이동·체결 결과를 비교하는 회귀 자료를 만든다. Node 모의 엔진과 Rust 엔진을 나란히 실행해 비교한 뒤 모의→소액 순서로 올린다. 금액의 정수/고정소수점 표현, 주문 멱등성, 감사 원장은 언어와 무관하게 필요하다. 학습·리서치까지 한 번에 재작성하지 않는다.

## 5. 실험 가정과 미결정 항목

**실험 가정:** 데모 본절 이동 +0.5%, 본절 가격 오프셋 0, 재진입 대기 30초, 합성 추세선/호가, 매도세금 0 등. 실제 비용·매수 추천·검증된 전략 수치가 아니다. 정확한 실행값은 해당 데모의 `config.json`을 따른다.

**아직 정할 내용:** 초기 손절 저점과 완충 폭, 본절 이동 상승 폭과 수수료·세금 포함 여부, 추세선 추출/라벨 기준, 재진입·동일 종목 물량 합산 규칙, 당일 청산 시각과 익일 보유 허용 범위, 종목별 금액·일일 손실 한도, 모의 성과 승격 기준, 데이터 보관 정책, 처리 지연·복구 목표.

**아직 확인할 내용:** 토스 실제 키 연결 및 거래소/세션별 주문·보호 기능, 대체 브로커 적합성, 강의 틱 패턴에 필요한 데이터 완전성, 실제 Bedrock 호출, Docker 이미지 빌드, AWS 배포·비용·장애 승계. 현재 테스트 통과를 이 검증의 대체로 사용하지 않는다.

## 6. 변경 이력

- **2026-10-29:** 사용자 확정 전략, 모의 v0 구현 선택, 목표 AWS 구조, 기록 범위와 누락, Rust 전환 판단을 문서화. 기존 구현의 언어·매매 로직·실거래 권한은 변경하지 않음.
